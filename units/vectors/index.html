    Vectors

    Positions, directions, light, normals and rays are all vectors. Five operations cover almost everything shaders do with them.

    Every drawing below can be dragged. The numbers update as you move.

    Arrows made of numbers

    A is a short list of numbers, written in brackets: (3, 2) in 2D, (3, 2, 1) in 3D. The numbers are its components, named x, y and z.

    The same list can mean two different things, and shaders use both all the time:

    • A position: a point in space, "3 to the right and 2 up from the origin".
    • A direction (or offset): "go 3 right and 2 up", from wherever you are. A light direction, a surface normal and a camera ray are directions.

    Either way, it helps to draw it as an arrow: from the origin to the point, or from anywhere in the direction. Drag the arrow's tip:

    In a shader a 3D vector is a float3 (see types). Nothing in the type says whether it is a point or a direction; that is up to you. Mixing them up is a common bug, and later lessons show where the difference matters (moving a direction ignores translation).

    Adding and subtracting

    To add two vectors, add their components: (1, 2) + (3, −1) = (4, 1). As arrows, put the second one at the tip of the first; the sum points to where you end up.

    Subtracting is the operation you will use most. B − A is the arrow that goes from A to B. "Direction from the surface to the light", "from the camera to this pixel's position", "from the sphere's centre to the ray origin": each is one subtraction.

    Scaling

    Multiplying a vector by a single number k multiplies every component: 2 × (1, 3) = (2, 6). The arrow keeps its direction and gets k times longer. A negative k flips it around; 0 shrinks it to nothing.

    Length

    How long is the arrow (3, 4)? Its components form the two short sides of a right-angled triangle, and the arrow is the long side. Pythagoras gives the length:

    In 3D a third term joins under the root: |v| = √(x² + y² + z²). The distance between two points is the length of their difference, distance(A, B) = length(B − A), which combines this chapter with the previous one.

    Cheaper comparisons. The square root is the expensive part. If you only need to know whether something is closer than r, compare the squared length with r² instead. The sphere test uses exactly this.

    Normalizing: keeping only the direction

    Often only the direction matters, not the length: which way the light comes from, which way a surface faces. Dividing a vector by its own length gives a vector of length exactly 1 pointing the same way. This is called , and a length-1 vector is a unit vector, often written with a hat: v̂.

    Unit vectors always end on the circle (in 3D, the sphere) of radius 1. That is what makes the dot product of two unit vectors equal to the cosine of the angle between them, the basis of all lighting.

    Watch for zero. normalize((0, 0, 0)) divides by zero and returns NaN, which turns pixels black or white and spreads through every calculation that touches it. Guard directions that can become zero, for example with normalize(v + 1e-6) or a length check.

    Which way is up

    A vector's numbers only mean something once you know which axis points where. Engines disagree, and every asset that moves between Blender, Unity and Unreal crosses these conventions:

    Build it in Unity HDRP

    A distance mask around a point uses everything in this unit: subtracting positions, a length, and a normalized direction. It also shows the one HDRP detail that trips everyone up: world space in HDRP shaders is camera-relative. Written for Unity 6 with HDRP 17; Unity 2022 LTS works the same apart from a few renamed menu entries.

    Shader GraphA Lit graph with a mask around a point.
    HLSL fileSphereMask.hlsl: distance, falloff and direction.
    C# scriptMaskCenter.cs: sends a transform's position to all shaders.
    1. Create the graph: in the Project window, Create > Shader Graph > HDRP > Lit Shader Graph. Open it and check the Graph Inspector > Graph Settings.
    2. Add a Position node and set Space to Absolute World. HDRP renders relative to the camera for precision, so World means "world position minus camera position". Positions you send from C# are absolute, so compare them with Absolute World.
    3. Save SphereMask.hlsl. In the graph, add a Custom Function node. Set Type to File, Source to SphereMask.hlsl and Name to SphereMask (without the _float suffix). Add the inputs Position (Vector 3), Center (Vector 3), Radius (Float), Softness (Float) and the outputs Mask (Float), Direction (Vector 3), in that order and with those types: they must match the function's parameters.
    4. Add a Vector 3 property with Reference _MaskCenter and untick Exposed so the global value reaches it. Connect it to Center; add Floats for Radius and Softness.
    5. Use Mask to lerp between two colours into Base Color, and Direction (remapped from −1..1 to 0..1) as a debug colour to see the normalized vector.
    6. Add MaskCenter.cs to an empty GameObject and move it around: the mask follows in edit mode too. Shader Graph also has a ready-made Sphere Mask node that does the same maths.
    #ifndef ATLAS_SPHERE_MASK_INCLUDED
#define ATLAS_SPHERE_MASK_INCLUDED

// 1 inside Radius, fading to 0 over Softness metres. Direction points from the centre to the pixel.
void SphereMask_float(float3 Position, float3 Center, float Radius, float Softness,
                      out float Mask, out float3 Direction)
{
    float3 toPixel = Position - Center;            // B - A: the arrow from the centre to the pixel
    float  d = length(toPixel);                    // sqrt(x*x + y*y + z*z)
    Mask = 1.0 - smoothstep(Radius, Radius + max(Softness, 1e-4), d);
    Direction = d > 1e-5 ? toPixel / d : float3(0, 1, 0);   // normalize, guarding against zero length
}

#endif
    using UnityEngine;

// Sends this object's world position to every shader as _MaskCenter.
[ExecuteAlways]
public class MaskCenter : MonoBehaviour
{
    static readonly int CenterId = Shader.PropertyToID("_MaskCenter");

    void Update()
    {
        Shader.SetGlobalVector(CenterId, transform.position);   // absolute world position, w = 0
    }
}

    Inside a hand-written HDRP shader the same conversion is GetAbsolutePositionWS(positionRWS), and back with GetCameraRelativePositionWS(positionWS).

    URP does not render camera-relative: World and Absolute World are the same position. Everything else is identical.

    Absolute World Position is the default output of the WorldPosition node; Unreal 5 uses large world coordinates (LWC) internally, so prefer the provided nodes over doing the maths with raw floats. Send the centre with a Material Parameter Collection vector parameter. Remember Unreal is Z-up and in centimetres.
