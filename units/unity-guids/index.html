    GUIDs and .meta Files

    How a Unity project keeps track of its assets: what .meta files hold, how every reference is a GUID plus a fileID, the ways references break, missing scripts and renamed fields, and the version control settings that prevent it.

    No prior knowledge needed. Applies to every Unity render pipeline.

    Every asset has a .meta file

    Next to every file and folder in a Unity project's Assets folder sits a second file with the same name plus .meta: Rock.png and Rock.png.meta. Unity hides them in the Project window, but they are the most important files you will never edit by hand. A .meta file holds two things:

    • a : a random 128-bit number written as 32 hexadecimal characters, created once when Unity first sees the file and never changed after;
    • the import settings: for a texture, sRGB, compression and max size; for a model, scale and materials. That is why import settings survive a re-export and travel to teammates through version control.
    fileFormatVersion: 2
guid: a3f19c2e7d5b4c1f8e0a6b9d2c4e7f10
TextureImporter:
  mipmaps:
    enableMipMap: 1
    sRGBTexture: 1
  maxTextureSize: 2048
  textureCompression: 1
  ...

    The GUID is the asset's real identity. Its path and name are only where it currently lives; Unity can move and rename it freely, because nothing in the project refers to it by path.

    A reference is a GUID plus a fileID

    Scenes, prefabs and materials are text files in Unity's YAML format (with Force Text serialization, the default). Open one and every link to another asset looks the same: {fileID, guid, type}. The GUID picks the file, through its .meta; the picks the object inside that file, because one file can hold many objects (a model holds meshes, materials, animations); the type says where Unity reads the data from:

    --- !u!23 &4410382217716409362
MeshRenderer:
  m_GameObject: {fileID: 7703127742196413985}
  m_Materials:
  - {fileID: 2100000, guid: 1d7c3a90e51f4b2c9a8d6e4f20b1c305, type: 2}
--- !u!114 &502911846
MonoBehaviour:
  m_GameObject: {fileID: 7703127742196413985}
  m_Script: {fileID: 11500000, guid: 9e4a0b7c1d2e3f405a6b7c8d9e0f1a7f, type: 3}
  speed: 4.5

    References inside the same file store only the fileID: the MeshRenderer above points at its GameObject that way. Everything that breaks in a Unity project breaks at one of these two numbers: the GUID no longer matches any .meta, or the fileID no longer matches any object inside the file.

    fileIDs inside files

    fileIDs are stable for a different reason in each kind of file:

    • Native assets (scenes, prefabs, materials, .asset files) store each object with a local ID, created when the object was created and saved with it.
    • Imported assets with one main object use a fixed number derived from its class: a texture's is 2800000 (Texture2D is class 28), a script's 11500000 (MonoScript is class 115).
    • Sub-objects of imported models (meshes, materials, child transforms in an FBX) get fileIDs that Unity computes from their names and types in the file.

    The last rule is the one that bites artists. Rename a mesh in Blender or Maya, re-export, and Unity sees a new object with a new fileID; the old one is gone:

    Keep object names in exported models stable, treat a rename as a breaking change, and check prefabs that use the model after re-exporting (why reimports break prefabs).

    How references break

    Since references use GUIDs, the rule is simple: anything that keeps a file together with its .meta is safe, anything that separates them is not. Try each action:

    Do file work inside Unity's Project window whenever you can. If you must use the file system (bulk moves, a merge tool), always move the .meta with its file, and let Unity refresh before touching anything else. When a reference is already broken, the fix is to restore the old .meta (from version control) rather than re-assigning every reference by hand.

    Missing references, missing scripts, renamed fields

    The Inspector shows two different empty states. None means the field holds nothing. Missing means it holds a GUID and fileID that point to nothing; the data is still in the file, waiting for the asset to come back. Restoring the asset (with its original .meta) restores every Missing reference at once.

    A missing script ("The referenced script on this Behaviour is missing") is the same problem for code: the component's m_Script GUID no longer matches a script's .meta. It happens when a script file is moved outside Unity without its .meta, deleted, or when its class no longer matches its file name. The component keeps its saved values until it is removed, so fix the script first.

    Fields are referenced by name. A saved component stores speed: 4.5; rename the field to moveSpeed and Unity finds no saved value for it, so every instance silently returns to the default. Keep the old name with an attribute:

    using UnityEngine;
using UnityEngine.Serialization;

public class Mover : MonoBehaviour
{
    // Was "speed". Without the attribute, every saved value would reset to the default.
    [FormerlySerializedAs("speed")]
    public float moveSpeed = 2f;
}

    For classes stored with [SerializeReference], the class name and namespace are saved too; [MovedFrom] (in UnityEngine.Scripting.APIUpdating) tells Unity the old name when you rename or move such a class.

    Version control settings

    A team project needs four settings, checked once:

    • Visible meta files (Project Settings > Version Control, mode Visible Meta Files, the default): .meta files exist on disk and can be committed.
    • Force Text serialization (Project Settings > Editor > Asset Serialization, the default): scenes and prefabs are readable YAML that diffs and merges.
    • Commit every .meta with its file, and ignore the folders Unity regenerates: Library, Temp, Obj, Logs, UserSettings, Build.
    • Large binaries (textures, models, audio) in Git LFS or a version control system built for them, and Unity's Smart Merge (UnityYAMLMerge) configured for scene and prefab conflicts.

    With those in place, the only remaining risk is human: a file committed without its .meta. The implementation chapter has a pre-commit check that refuses exactly that. Collisions are not a risk worth thinking about:

    Working with GUIDs in tools

    Editor scripts work with GUIDs through AssetDatabase: AssetPathToGUID and GUIDToAssetPath convert between the two, and TryGetGUIDAndLocalFileIdentifier gives both numbers for any object. Two practical uses:

    • Who uses this asset? Because references are text, searching all .unity, .prefab, .mat, .asset and .controller files for an asset's GUID finds every user, including ones not loaded in any open scene.
    • What is broken? A SerializedProperty of type ObjectReference whose value is null but whose stored instance ID is not zero is a Missing reference. Walking every component in scenes and prefabs finds them all.

    Both tools are in the next chapter. Addressables uses the same GUIDs underneath: an AssetReference stores the target's GUID, which is why it survives renames (loading by reference).

    Set it up in Unity

    Three layers of protection: the project settings that make references visible and mergeable, a pre-commit check that refuses a file without its .meta, and two editor tools that answer "who uses this?" and "what is broken?". Nothing here depends on the render pipeline. Written for Unity 6; Unity 2022 LTS works the same apart from a few renamed menu entries (Build Profiles was Build Settings).

    Engine settingsVersion Control and Asset Serialization settings.
    Version control.gitignore, .gitattributes and a pre-commit hook.
    Editor scriptGuidTools.cs: copy GUID, find references, find Missing.
    1. Open Edit > Project Settings > Version Control and check that Mode is Visible Meta Files. Then Editor > Asset Serialization > Mode: Force Text. Both are the defaults in new projects; old projects may differ.
    2. Add .gitignore and .gitattributes to the repository root (next to Assets). The attributes send binaries to Git LFS (run git lfs install once per machine) and mark scenes and prefabs for Unity's merge tool.
    3. Configure Smart Merge: in your git config, add a merge driver named unityyamlmerge whose command runs UnityYAMLMerge merge -p %O %B %A %A from the Unity install's Data/Tools folder (Unity's Smart Merge page lists the exact path per platform).
    4. Save pre-commit as .git/hooks/pre-commit and make it executable (chmod +x; on Windows, Git Bash runs it as is). From now on a commit that adds an asset without its .meta, or deletes one but keeps the .meta, is refused with the file name.
    5. Put GuidTools.cs in an Editor folder. Right-click any asset: Atlas > Copy GUID and Atlas > Find References In Project. The second lists every scene, prefab, material and asset file that contains the GUID; click a line in the Console to ping the file.
    6. Run Tools > Atlas > Find Missing References with your scenes open. It walks every component of the open scenes and of every prefab asset, logs missing scripts and Missing object references with the object path and field name, and pings the object when you click the log.
    7. When something is Missing: look up the asset in version control history, restore its original .meta (or the whole file and .meta), and let Unity refresh. The references come back without reassigning anything.
    #if UNITY_EDITOR
using System.IO;
using System.Linq;
using UnityEditor;
using UnityEditor.SceneManagement;
using UnityEngine;

public static class GuidTools
{
    static readonly string[] TextAssets = { ".unity", ".prefab", ".mat", ".asset", ".controller", ".overrideController", ".anim", ".playable", ".shadergraph", ".shadersubgraph", ".vfx" };

    [MenuItem("Assets/Atlas/Copy GUID")]
    static void CopyGuid()
    {
        string guid = AssetDatabase.AssetPathToGUID(AssetDatabase.GetAssetPath(Selection.activeObject));
        EditorGUIUtility.systemCopyBuffer = guid;
        Debug.Log($"GUID {guid} copied");
    }

    [MenuItem("Assets/Atlas/Find References In Project")]
    static void FindReferences()
    {
        string target = AssetDatabase.GetAssetPath(Selection.activeObject);
        string guid = AssetDatabase.AssetPathToGUID(target);
        if (string.IsNullOrEmpty(guid)) return;

        var files = Directory.GetFiles("Assets", "*.*", SearchOption.AllDirectories)
                             .Where(f => TextAssets.Contains(Path.GetExtension(f))).ToArray();
        int hits = 0;
        try
        {
            for (int i = 0; i < files.Length; i++)
            {
                if (EditorUtility.DisplayCancelableProgressBar("Find references", files[i], (float)i / files.Length)) break;
                if (!File.ReadAllText(files[i]).Contains(guid)) continue;   // references are plain text: {fileID, guid, type}
                string path = files[i].Replace('\\', '/');
                Debug.Log($"{target} is used by {path}", AssetDatabase.LoadMainAssetAtPath(path));
                hits++;
            }
        }
        finally { EditorUtility.ClearProgressBar(); }
        Debug.Log($"{hits} file(s) reference {target}");
    }

    [MenuItem("Tools/Atlas/Find Missing References")]
    static void FindMissing()
    {
        int count = 0;
        for (int s = 0; s < EditorSceneManager.sceneCount; s++)
            foreach (var root in EditorSceneManager.GetSceneAt(s).GetRootGameObjects())
                count += Check(root, EditorSceneManager.GetSceneAt(s).path);

        foreach (string guid in AssetDatabase.FindAssets("t:Prefab"))
        {
            string path = AssetDatabase.GUIDToAssetPath(guid);
            var prefab = AssetDatabase.LoadAssetAtPath<GameObject>(path);
            if (prefab != null) count += Check(prefab, path);
        }
        Debug.Log($"{count} missing reference(s) found");
    }

    static int Check(GameObject root, string where)
    {
        int count = 0;
        foreach (var t in root.GetComponentsInChildren<Transform>(true))
        {
            foreach (var c in t.GetComponents<Component>())
            {
                if (c == null) { Debug.LogWarning($"Missing script on {PathOf(t)} in {where}", t.gameObject); count++; continue; }
                var so = new SerializedObject(c);
                var it = so.GetIterator();
                while (it.NextVisible(true))
                {
                    // Missing: a reference is stored (non-zero instance ID) but resolves to nothing.
                    if (it.propertyType == SerializedPropertyType.ObjectReference &&
                        it.objectReferenceValue == null && it.objectReferenceInstanceIDValue != 0)
                    {
                        Debug.LogWarning($"Missing reference: {PathOf(t)} > {c.GetType().Name}.{it.propertyPath} in {where}", t.gameObject);
                        count++;
                    }
                }
            }
        }
        return count;
    }

    static string PathOf(Transform t) => t.parent == null ? t.name : PathOf(t.parent) + "/" + t.name;
}
#endif
    #!/bin/sh
# .git/hooks/pre-commit: refuse commits that separate Unity assets from their .meta files.
IFS='
'
fail=0
tracked() { git ls-files --error-unmatch -- "$1" >/dev/null 2>&1; }   # in the index (staged or committed)

# Added files and their folders need a .meta in the index.
for f in $(git diff --cached --name-only --diff-filter=A -- Assets); do
  case "$f" in *.meta) continue ;; esac
  if ! tracked "$f.meta"; then echo "no .meta for added file: $f"; fail=1; fi
  d=$(dirname "$f")
  while [ "$d" != "Assets" ] && [ "$d" != "." ]; do
    if ! tracked "$d.meta"; then echo "no .meta for folder: $d"; fail=1; fi
    d=$(dirname "$d")
  done
done

# Deleted files must take their .meta with them.
for f in $(git diff --cached --name-only --diff-filter=D -- Assets); do
  case "$f" in *.meta) continue ;; esac
  if tracked "$f.meta"; then echo "deleted $f but kept $f.meta"; fail=1; fi
done

if [ $fail -ne 0 ]; then
  echo "Commit refused: stage the .meta files listed above (git add), or remove them."
  exit 1
fi
exit 0

    Plastic SCM / Unity Version Control and Perforce handle .meta files through Unity's integration and their own ignore files; the same rules apply: commit every .meta with its asset, never commit Library.

    Nothing pipeline specific: the same settings, hook and tools apply to URP and HDRP projects alike.
    Unreal has no .meta files: each .uasset stores its own identity, and references are by object path. Moving assets outside the editor breaks them; inside the editor a move leaves a redirector behind. Run Fix Up Redirectors on folders before deleting them.
