    Foliage Vertex Data: Pivots and Hierarchy

    What a wind shader needs per vertex and where to store it: vertex colours, UV channels and textures, the precision of 8-bit, half and float data, a pivot layout for branch hierarchies, Pivot Painter 2, baking in tree tools, and what breaks the data, built for Unity HDRP and Unreal.

    Builds on Coordinate Spaces and Procedural Trees. Build chapters for Unity HDRP and Unreal Engine.

    Data a wind shader needs per vertex

    A vertex shader sees one vertex at a time: its position, normal, UVs and colour. To bend a branch it must rotate that vertex around the point where the branch is attached. Nothing in a normal mesh says where that is. Rotating around the object origin, the only point the shader knows, tears branches off the trunk:

    So foliage meshes carry extra data per vertex: the of the branch the vertex belongs to, and often the pivots of its parents, a random phase so branches do not move in sync, and masks that say how stiff the part is. Tree tools write this data; the shader reads it (branch sway).

    Where the data can live

    Five places can carry extra data, with different precision and cost:

    WhereFormatTypical foliage useLimits
    Vertex colourRGBA, 8 bits per channel (0–1)Masks: flutter, stiffness, phase, AO256 levels: fine for masks, too coarse for positions
    UV channelsUnity: up to 8 channels of up to 4 floats. Unreal: up to 8 channels of 2 floatsPivots, hierarchy level, branch phaseUnreal stores UVs as 16-bit floats unless Use Full Precision UVs is on; Unity mesh compression can quantise them
    Normals and tangents3–4 floatsNot free: lighting needs themDo not hide data here
    Textures, indexed by a UVAny texture formatPivot Painter 2: pivots, axes, parent index per elementOne vertex texture fetch per lookup; needs nearest filtering and no mips
    Per-instance dataInstance bufferRandom phase, colour variation, wind strength per treeSame for the whole mesh: not per branch

    Extra data costs memory per vertex, once per mesh. Instances share it, so it rarely matters for memory; it matters for vertex fetch bandwidth, which every pass pays (main, depth, shadows, motion vectors):

    Precision: 8-bit, 16-bit and 32-bit

    Positions need more precision than masks. An 8-bit vertex colour has 256 levels, a centimetre-scale step on a small plant and decimetres on a tree. A 16-bit half float keeps 11 significant bits, so its step grows with the value: around a millimetre near 1 m, about 8 mm at 18 m. Normalised 16-bit values store the position relative to the bounds and keep a constant step:

    Two practical consequences. In Unreal, enable Use Full Precision UVs on foliage meshes that store pivots in UVs, or accept half-float steps on large trees. In Unity, keep Mesh Compression off on those meshes and check that the Player setting Vertex Compression excludes the UV channels you use. Masks, phases and stiffness are fine in 8 bits.

    Pivots in UV channels

    The common approach writes each vertex's pivot into spare UV channels. A level-1 branch needs three floats for its pivot, a level-2 twig another three, plus whatever else should vary per part. Count the floats before choosing a layout, because Unreal's UV channels hold two floats each:

    The Foliage units use one layout throughout, chosen to work in both engines (two floats per channel, UV1 left free for lightmaps):

    DataChannelValue
    Texture coordinatesUV0Albedo, normal and mask maps
    Lightmap UVsUV1Left free: Unity and Unreal both use this index for lightmaps
    Branch pivot (level 1)UV2.xy, UV3.xObject-space position where the branch leaves the trunk
    Branch phaseUV3.yRandom 0–1 per branch, so neighbours do not sway in sync
    Twig or card pivot (level 2)UV4.xy, UV5.xWhere the twig or leaf card attaches to its branch
    Hierarchy levelUV5.y0 trunk, 1 branch, 2 twig or card
    MasksVertex colourR flutter (leaf edges), G per-leaf phase, B stiffness (1 = stiff), A ambient occlusion

    Trunk vertices store the object origin and level 0. A branch's own pivot is stored on every vertex of that branch, including the vertices of its twigs, which also store their own level-2 pivot. The rotation axis does not need to be stored: the wind shader builds it from the wind direction and the up axis, which is accurate enough for sway.

    Hierarchy: parents move children

    A twig on a swaying branch must sway with the branch and add its own motion. The shader therefore applies rotations from the finest level outwards: the twig around its pivot, then the result around the branch pivot, then around the trunk base. Each stored pivot is in the rest pose; because the parents' rotations are applied afterwards, they carry the twig's pivot along with everything else:

    Two or three levels are enough for almost every game tree: trunk, branches, and leaves or twigs. Pivot Painter 2's foliage shader supports four. Each level costs one rotation per vertex in every pass that runs the vertex shader.

    Data in textures: Pivot Painter 2

    UV channels run out quickly when every level needs pivot, axis, length and parent. Unreal's takes the other route: each element (branch, twig, leaf) gets an index, the mesh stores only that index in one UV channel, and the data lives in textures, one texel per element. The vertex shader looks the element up, reads its parent index, and walks up the hierarchy:

    Pivot Painter 2 writes a 16-bit texture with pivot positions and parent indices and an 8-bit texture with the element's X axis and extent, stored without mips and sampled with nearest filtering. Its PivotPainter2FoliageShader material function handles up to four levels. The cost moves from vertex memory to vertex texture fetches: one or two per level per vertex.

    The same idea works in Unity with a small custom texture or a structured buffer indexed by element (structured buffers); there is no built-in tool.

    Baking the data in tree tools

    • SpeedTree writes its own wind data into the mesh when exporting for its engine shaders; the layout belongs to the SpeedTree shaders, so use those shaders or export FBX and bake your own.
    • Houdini: the tree tools know each point's branch, level and root. An Attribute Wrangle copies the root position of the point's branch into vector attributes, and the FBX export turns attributes named uv2, uv3… into extra UV sets. The build chapter has the wrangle.
    • Blender: Geometry Nodes can capture each branch's start position and store it as a 2D vector attribute, which exports as a UV map.
    • 3ds Max: Pivot Painter 2's MAXScript writes the textures for Unreal from a hierarchy of separate objects.

    What breaks the data

    Pivot data is stored in object space, and plenty of tools change object space without touching UVs:

    • Static batching and mesh combining transform vertices into world or combined space, but the stored pivots stay in the old object space. Every branch then rotates around a point near the world origin. Keep wind foliage out of static batching and combine tools; instancing keeps object space intact.
    • Axis and unit conversion. FBX import converts positions to the engine's axes and units (Unity mirrors from right-handed FBX; Unreal converts to Z-up centimetres), but UV data is copied as is. Either write the pivots in engine space in the DCC tool or convert them in the shader, and verify with a test branch.
    • Compression and quantisation: mesh compression, 16-bit UVs (precision).
    • LOD and optimisation tools that rebuild meshes and drop or average extra UV channels. Check the LODs, not only LOD0.
    • Non-uniform scale on instances distorts rotations; scale uniformly and vary size per instance.

    Build it in Unity HDRP

    The route bakes the layout in Houdini, keeps it intact through the Unity import, decodes it in Shader Graph and makes it visible with a gizmo, so a wrong pivot is found before wind is added. Written for Unity 6 with HDRP 17; Unity 2022 LTS works the same apart from a few renamed menu entries.

    Substance DesignerBakePivots: a Houdini Attribute Wrangle that writes pivots, phase and level to UV sets.
    HLSL fileFoliagePivots.hlsl: decodes the layout in a Custom Function.
    C# scriptPivotGizmos.cs: draws every stored pivot on the selected tree.
    1. In Houdini, after the tree is built, make sure every point has i@branch_id and i@level, and that the branch curves (the Labs Tree Tools output them) carry branch_id and parent_id. Add an Attribute Wrangle with the BakePivots code, the mesh in input 0 and the curves in input 1. Leave space at 0 for Unity.
    2. Export FBX. Houdini names UV sets after the attributes uv, uv2, uv3…, so the wrangle writes uv3–uv6 to land in channels 2–5 and leave channel 1 free for lightmaps.
    3. Import into Unity with Mesh Compression off (the tree import script does it). In Project Settings > Player > Other Settings > Vertex Compression, untick the TexCoord channels that hold pivots.
    4. Add PivotGizmos.cs to an instance of the tree and select it. Cyan spheres must sit where branches leave the trunk, green ones where twigs leave branches. If they appear mirrored, toggle Mirror X; if they float far away, the mesh was combined or batched.
    5. In the foliage graph, add four UV nodes (channels UV2, UV3, UV4, UV5) and a Float property MirrorX (default 1). In the graph, add a Custom Function node. Set Type to File, Source to FoliagePivots.hlsl and Name to FoliagePivots (without the _float suffix). Add the inputs UV2 (Vector 4), UV3 (Vector 4), UV4 (Vector 4), UV5 (Vector 4), MirrorX (Float) and the outputs BranchPivot (Vector 3), BranchPhase (Float), TwigPivot (Vector 3), Level (Float), in that order and with those types: they must match the function's parameters. These outputs feed the wind function in Foliage Wind.
    6. Mark wind foliage as not Batching Static (Static Editor Flags), or keep it on terrain or an instanced renderer, so object space stays intact.
    // Houdini Attribute Wrangle (Run Over: Points) on the tree mesh: BakePivots
// Input 0: the tree mesh. Each point has i@branch_id (which branch it belongs to) and i@level (0 trunk, 1 branch, 2 twig/card).
// Input 1: one polyline per branch, ordered root -> tip, with prim attributes i@branch_id and i@parent_id (-1 for the trunk).
// Writes the layout used by the Foliage units:
//   channel 2 = (L1 pivot x, L1 pivot y)   channel 3 = (L1 pivot z, branch phase)
//   channel 4 = (L2 pivot x, L2 pivot y)   channel 5 = (L2 pivot z, level)
// FBX UV sets follow the attribute names: "uv" is channel 0, "uv2" channel 1, "uv3" channel 2 ...
// so the four attributes go to uv3..uv6, landing in channels 2..5 (channel 1 stays free for lightmaps).

int space = chi("space");          // 0 = engine-neutral (Houdini metres, Y-up), 1 = Unreal (x, z, y) * 100

vector to_engine(vector p; int space)
{
    if (space == 1) return set(p.x, p.z, p.y) * 100.0;   // as Houdini Engine maps to Unreal; FBX import may add a mirror: verify
    return p;
}

int  bid   = i@branch_id;
int  lvl   = i@level;
int  prim  = findattribval(1, "prim", "branch_id", bid);
vector root = prim >= 0 ? point(1, "P", primpoint(1, prim, 0)) : {0, 0, 0};
int  parent = prim >= 0 ? prim(1, "parent_id", prim) : -1;
int  pprim  = parent >= 0 ? findattribval(1, "prim", "branch_id", parent) : -1;
vector proot = pprim >= 0 ? point(1, "P", primpoint(1, pprim, 0)) : {0, 0, 0};

vector L1 = {0, 0, 0}, L2 = {0, 0, 0};
float phase = 0;
if (lvl == 1) { L1 = root;  phase = rand(bid * 13.17); }
if (lvl >= 2) { L1 = proot; L2 = root; phase = rand(parent * 13.17); }

L1 = to_engine(L1, space);
L2 = to_engine(L2, space);
v@uv3 = set(L1.x, L1.y, 0);        // channel 2
v@uv4 = set(L1.z, phase, 0);       // channel 3
v@uv5 = set(L2.x, L2.y, 0);        // channel 4
v@uv6 = set(L2.z, lvl, 0);         // channel 5
    #ifndef ATLAS_FOLIAGE_PIVOTS_INCLUDED
#define ATLAS_FOLIAGE_PIVOTS_INCLUDED

// Decodes the Foliage-unit layout from UV channels 2..5 (object space):
//   UV2.xy, UV3.x  branch pivot     UV3.y  branch phase
//   UV4.xy, UV5.x  twig pivot       UV5.y  hierarchy level (0, 1, 2)
// MirrorX: 1 if the importer mirrored the mesh's X axis (Unity does for right-handed FBX), else 0.
// Verify once with a test tree: draw the pivots with the PivotGizmos script.
void FoliagePivots_float(float4 UV2, float4 UV3, float4 UV4, float4 UV5, float MirrorX,
                         out float3 BranchPivot, out float BranchPhase, out float3 TwigPivot, out float Level)
{
    float sx = MirrorX > 0.5 ? -1.0 : 1.0;
    BranchPivot = float3(UV2.x * sx, UV2.y, UV3.x);
    BranchPhase = UV3.y;
    TwigPivot   = float3(UV4.x * sx, UV4.y, UV5.x);
    Level       = UV5.y;
}
#endif
    // Assets/Scripts/PivotGizmos.cs: add to a tree in the scene to see the stored pivots.
// Draws a sphere at every distinct branch pivot (UV2.xy, UV3.x) and twig pivot (UV4.xy, UV5.x).
using System.Collections.Generic;
using UnityEngine;

[ExecuteAlways]
public class PivotGizmos : MonoBehaviour
{
    public bool mirrorX = true;      // must match the material's MirrorX
    public float size = 0.05f;
    readonly List<Vector2> a = new(), b = new(), c = new(), d = new();

    void OnDrawGizmosSelected()
    {
        var mf = GetComponentInChildren<MeshFilter>(); if (mf == null || mf.sharedMesh == null) return;
        var m = mf.sharedMesh; m.GetUVs(2, a); m.GetUVs(3, b); m.GetUVs(4, c); m.GetUVs(5, d);
        if (a.Count == 0 || b.Count == 0) return;
        var seen = new HashSet<Vector3Int>();
        Gizmos.matrix = mf.transform.localToWorldMatrix;
        float sx = mirrorX ? -1f : 1f;
        for (int i = 0; i < a.Count; i++)
        {
            Draw(new Vector3(a[i].x * sx, a[i].y, b[i].x), Color.cyan, seen);
            if (c.Count > i && d.Count > i && d[i].y > 1.5f) Draw(new Vector3(c[i].x * sx, c[i].y, d[i].x), Color.green, seen);
        }
    }

    void Draw(Vector3 p, Color col, HashSet<Vector3Int> seen)
    {
        if (!seen.Add(Vector3Int.RoundToInt(p * 1000f))) return;   // one sphere per distinct pivot
        Gizmos.color = col; Gizmos.DrawSphere(p, size);
    }
}

    Why not world space? Instances share one mesh, so the data must be relative to the mesh. The shader adds the instance transform like it does for every other position.

    Build it in Unreal Engine

    Two routes in Unreal: the same UV layout read with TexCoord nodes, or Pivot Painter 2 with its textures and material functions. Written for Unreal Engine 5.6 and later. Substrate is production-ready from 5.7; check Project Settings > Rendering > Substrate to see which material model a project uses.

    Custom node HLSLFoliagePivots.ush: decodes the UV layout.
    Material FunctionOr PivotPainter2FoliageShader with the Pivot Painter 2 textures.
    1. Bake with space = 1 in the Houdini wrangle so pivots are written in Unreal's Z-up centimetres. Import the FBX and, in each LOD's Build Settings, enable Use Full Precision UVs; check UV Channels = 6 in the static mesh details.
    2. Place a test tree, then verify: in the material, output the distance between Pre-Skinned Local Position and the decoded branch pivot as Emissive. It must be near zero at the base of every branch. A pattern that looks mirrored means the FBX import added a mirror: negate the matching axis in the Custom node.
    3. Add a Custom node with FoliagePivots.ush, inputs from TexCoord nodes with coordinate indices 2–5. The outputs feed the wind setup in Foliage Wind.
    4. Pivot Painter 2 route. Run the Pivot Painter 2 MAXScript on a hierarchy of separate objects in 3ds Max (or a Blender port), export the mesh and the two textures. Import the textures with the settings the tool states: no mipmaps, Nearest filter, sRGB off, HDR compression for the 16-bit EXR. Use PivotPainter2FoliageShader in the material and untick Tangent Space Normal as its documentation describes.
    5. Foliage painted with the Foliage tool is instanced (Instanced or Hierarchical Instanced Static Mesh), which keeps local space intact. Avoid merging wind foliage with Merge Actors.
    // Custom node "FoliagePivots". Inputs: UV2, UV3, UV4, UV5 (float2, TexCoord[2..5]).
// Output Type: CMOT Float 3 (branch pivot, local space, cm). Additional Outputs: BranchPhase (Float 1),
// TwigPivot (Float 3), Level (Float 1).
// Assumes the pivots were written in Unreal space in Houdini (space = 1 in BakePivots). Use them with
// Local Position (Pre-Skinned Local Position) and transform the offset to world with TransformVector.
BranchPhase = UV3.y;
TwigPivot   = float3(UV4.x, UV4.y, UV5.x);
Level       = UV5.y;
return float3(UV2.x, UV2.y, UV3.x);
